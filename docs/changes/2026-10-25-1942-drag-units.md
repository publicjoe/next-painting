# Drag and drop for units

Date and time: 2026-10-25 19:42

## Summary

Units can now be dragged. A grip on each row of the unit table reorders the unit within its project, and dragging a row onto a project in the sidebar moves it to the end of that project. It uses the same mechanism as the sidebar (dnd-kit, the same namespaced ids, drop line, overlay, live announcer, hover-to-open of closed categories and keyboard support). Because a dnd-kit context cannot see draggables outside itself, the context was lifted out of the sidebar into a provider that wraps both the sidebar and the main area. Each unit row also has a Move menu (Move up, Move down, Move to another project) for people who do not drag.

The stored data format is unchanged: a unit's place is its position among the `models` of its project in the array, and `lib/validate.ts` and `lib/migrate.ts` needed no change.

## How the context was lifted

- `components/PaintDndProvider.tsx` (new) owns everything that used to live in `Sidebar`: the sensors, the keyboard coordinate getter, collision detection, the announcer, the drag state, the cancel-on-data-change effect, the hover-to-open timer and the `DragOverlay`. `PaintLogApp` wraps `Sidebar` and `<main>` in it and passes the three move handlers.
- The collapsed state of categories stays in `Sidebar`. The sidebar registers two functions with the provider (is a category open, open a category), which the provider reads when a drag needs them, never during a render.
- `Sidebar` and `ModelTable` read the drag state (`dragItem`, `drop`, `move`) with `useDragDrop()` to draw their own indicators.

## Changes

- **Reducer** (`lib/state.ts`)
  - New `MOVE_MODEL { id, toProjectId, toIndexInProject }`, mirroring `MOVE_PROJECT`: indexes count positions after the unit is removed and are clamped, a move to the same place returns the same state object, `projectId` is updated when the project changes, and unknown ids or projects are ignored. No id-keyed object lookups, so `__proto__` ids are harmless.
- **Ids and resolver** (`lib/dnd-ids.ts`, `lib/drop-target.ts`)
  - New kinds `unit` (a unit row) and `ulist` (a project's unit table, the target when a project has no rows). New pure `resolveUnitDrop`: a unit row is before or after it by pointer half, a sidebar project row or an empty project's table is the end of that project, anything else (category headers, lists, categories) is no move.
- **Drag logic** (`lib/sidebar-dnd.ts`)
  - `resolveDrop`, `keyboardSlots`, `stepKeyboardDrop` and the announcer take the units as an optional last argument, so existing callers are unchanged. A keyboard unit drag steps through the table slots and then each sidebar project in order. A closed category with projects is one stop on its header: it holds no move, and when it opens (after the hover delay) the step lands on its first project.
  - Collision detection is filtered by what is dragged: units hit unit rows, sidebar project rows, closed headers (so they open on hover) and an empty table; project and category drags never hit unit rows. A unit released over nothing hits nothing (projects fall back to the nearest row, as before).
  - Announcements and cancellations speak units by name: for example `Moved unit "X" to project "Y", position n of m.`
- **Unit table** (`components/ModelTable.tsx`, `components/ProjectList.tsx`)
  - A grip ("Drag <unit>") in the name cell, so the table keeps its seven columns and valid markup. Rows are sortable; the table is the drop target for an empty project. The insertion line is an inset shadow on the row's cells, because a table row can hold only cells.
  - A Move menu per row ("Move unit <name>"), with targets labelled "Project (Category)" and keyed by project id. Its result is spoken in a status region in the table.
  - Focus after a move: for a Move menu reorder, the unit's own Move button. For a keyboard drag reorder, focus stays on the grip. When a unit leaves the table (menu, keyboard or pointer), focus goes to the unit that now holds the same place, or the new-unit field when none is left.
- **Move menu** (`components/MoveMenu.tsx`)
  - New `fixed` option, used by the unit table: the menu is positioned against the viewport, because the table's `overflow-x-auto` would clip an absolutely positioned one. It closes when the page scrolls or resizes (scrolling the menu itself is ignored).
- **Sidebar** (`components/Sidebar.tsx`)
  - Drag state and the `DndContext` moved out; the project row a unit would land on is outlined (a unit goes to the end of a project, so there is no line).
- **App** (`components/PaintLogApp.tsx`)
  - Wraps the screen in the provider, builds the Move targets in sidebar order, and adds `handleMoveModel`. It does not pin the selection as `handleMoveProject` does, because moving a unit changes neither project order nor category order, so the shown (possibly implicit first) project cannot change.
- **Docs**
  - `README.md` describes unit reordering and the new component. `docs/qa/2026-10-24-2329-qa-review.md` notes that a unit released over nothing moves nothing, and adds two advisories (unit dragging verified in Chromium and jsdom only, and drag announcements naming the project but not its category).

## Caveats

- Unit dragging was checked with Vitest in jsdom (keyboard path only) and Playwright in Chromium (keyboard and pointer). Touch dragging of a unit grip, other browsers, real devices and a real screen reader were not checked.
- A pointer drag released over nothing moves nothing for units, but still moves the nearest row for projects and categories (the existing accepted trade-off).
- Drag announcements say `project "Party"` without its category, so two projects with the same name in different categories sound alike. The Move menu labels them "Party (D&D)" and "Party (WH40k)".
- The unit Move menu closes when the page scrolls or resizes. A phone with the on-screen keyboard open was not checked.
- Undo of a delete restores units at their recorded array index, as for projects and categories, so a delete, then a move, then an undo can restore a unit to a position that no longer matches what was seen. The data stays valid.
