# Unique category and project names

Date and time: 2026-10-25 20:08

## Summary

Two naming rules are now enforced everywhere a name can change: no two categories may share a name, and no two projects in the same category may. The same project name in different categories is still allowed. Names are compared as the sidebar already compared category names (trim, Unicode NFC, lower case). That comparison moved out of `Sidebar` into one shared pure module, `lib/names.ts`, which every check now uses.

Categories already refused a duplicate on add and rename. This change adds the same for projects (add, rename and move between categories), a reducer backstop for both, a refusal when an undo would recreate a clash, and rejection of an import file that contains a duplicate. Stored data that already holds duplicates still loads and works.

## Changes

- **Shared rule** (`lib/names.ts`, new)
  - `canonicalName`, `sameName`, `findCategoryClash`, `findProjectClash` (both take an `exceptId` so a rename never clashes with itself, which allows a case or spacing change of the item's own name) and `findMoveClash` (a move into the project's own category is a reorder and never a clash). Maps and Sets only, so `__proto__` names and ids are harmless.
  - The message builders used by the forms, the Move menu, the drag announcer and the undo and import checks, so wording stays in one place.
  - `findCategoryRenameClash` and `findProjectRenameClash`, used by both the forms and the reducer so they agree: a rename whose compared name equals the item's own current compared name (and, for a project, with the category unchanged) is always allowed, even beside a stored namesake.
  - `findImportNameClash` (linear, a Map of Sets) and `findRestoreClash`.
- **Reducer** (`lib/state.ts`)
  - `ADD_CATEGORY`, `UPDATE_CATEGORY`, `ADD_PROJECT`, `UPDATE_PROJECT` and `MOVE_PROJECT` return the same state object on a clash. Only the item being changed is checked, and an update is checked only when the compared name (or, for a project, the category) changes, so renames of other items in a dirty dataset and a case-only change of a duplicate itself still work.
  - `RESTORE_ITEMS` (undo of a delete) skips a category or project whose name has been taken since the delete, and so its children, which are then orphans and are skipped by the existing rule. Names are checked against the current data, not against the other items restored with it.
- **Add and rename a project** (`components/ProjectList.tsx`, `components/InlineEditText.tsx`, `components/PaintLogApp.tsx`)
  - A clash shows a `role="alert"` message naming the name and category, keeps the typed value, does not dispatch, and sets `aria-invalid` and `aria-describedby` on the field. The add form keeps focus in its field. A refused rename mirrors the category rename: focus returns to the field, Escape reverts and clears the message, and the message says so. The messages are tied to the category or project they were raised for and disappear when another is chosen.
  - `InlineEditText` gained optional `invalid` and `describedBy` props, and the project name field is keyed by project id. `ProjectList` gained a `categoryProjects` prop.
  - `handleAddProject`, `handleAddCategory` and `handleMoveProject` in `PaintLogApp` also check, so the selection never follows an action the reducer would refuse.
- **Moves** (`components/Sidebar.tsx`, `components/PaintDndProvider.tsx`, `lib/sidebar-dnd.ts`)
  - Move menu: choosing "Move to <category>" for a clashing destination refuses the move and shows the reason in the sidebar alert. The option is left selectable instead of disabled, because the menu skips `aria-disabled` items when arrowing, which would hide the reason from keyboard and screen reader users.
  - Drag and keyboard drags: the drop is refused on release. The announcer says "cannot be dropped here: category ... already has a project named ..." while resting on a clashing slot and "was not moved: ..." on drop, and the sidebar shows the visible alert (through a new `refuse` function in the handle the sidebar registers with the provider). No drop line or highlight is drawn for a refused target. Keyboard stepping still passes over clashing slots, so nobody is trapped. A refusal clears when the next drag starts.
- **Undo** (`components/PaintLogApp.tsx`)
  - Before restoring, `findRestoreClash` is checked. A clash refuses the whole undo with an alert ("Could not undo: a project named ... already exists in category ... Rename or delete it, then try Undo again."), and the toast stays so it can be retried. Through the app nothing is restored partially, and nothing is skipped silently.
- **Import** (`components/PaintLogApp.tsx`)
  - After migration, `findImportNameClash` runs and a clash goes to the existing `importError` banner, naming the clash. It is not in `isAppState`, `lib/validate.ts` or `lib/migrate.ts`, because stored data with duplicates must keep loading. It runs on the migrated state, so two long names that only become equal when shortened to 120 characters are also rejected (the "adjusted" notice flow is unchanged and only reached when there is no clash).
- **Docs**: `README.md` (naming behaviour, `names.ts` in the layout table) and `docs/qa/2026-10-24-2329-qa-review.md` (accepted trade-offs for duplicates in stored data, undo refusal, the selectable Move option, no drop hint on refusal, focus held on a refused rename and import rejecting rather than renaming; the screen reader advisory now covers the new messages).

## Caveats

- A Move menu option for a clashing category looks available and refuses when chosen.
- A pointer drag released over a clashing target draws no line and is refused on release, with a message; there is no "not allowed" cursor.
- Undoing the delete of one of a pair of stored duplicates is refused while the other exists. The toast times out after eight seconds, which loses the undo.
- The reducer's `RESTORE_ITEMS` skips per item (and so its children), while the app refuses a whole undo. Through the app the reducer's skip is never reached.
- Behaviour was checked in jsdom and Chromium only. Safari, Firefox, touch and a real screen reader were not checked (focus return after a refused rename and the new announcements in particular).
