## Accepted trade-offs

Known, reviewed and deliberately left as they are.

- **Compact touch targets in the model table.** Status checkboxes and trash buttons are about 28px and the sidebar chevron and rename and delete buttons are about 32px. These pass WCAG 2.2 AA (SC 2.5.8, 24px) but are under the 44px recommendation on mobile. The compact table is the owner's choice for vertical space.
- **Three-toast Undo limit.** Past three stacked delete toasts, the oldest silently loses Undo (`MAX_TOASTS`).
- **Selection fallback after undo.** Undoing a project delete in a different category selects the first project. Harmless.
- **Undo index caveat for moves.** Undo restores deleted items at their recorded array index, and reordering changes the array. Deleting a category or project, then moving others, then restoring can put the item back at a position that no longer matches what the user saw. This covers categories and projects, including delete, then move, then restore. The data stays valid (no orphans or duplicates), only the position can differ.
- **Selection after undo can show the wrong heading.** After an undo, the selected project and category can disagree, so the main heading may show the wrong category until something is selected again.
- **Releasing a pointer drag away from any target still moves the item.** The collision detection falls back to the nearest row, so letting go outside the list moves the item there. The drop line shows where it will land before release, and there is no undo for a move. A future change could return no collision when the pointer is outside the category nav.
- **The cancel on another tab's change is narrower than the ADR's wording.** ADR 0001 says to cancel on `REPLACE_STATE`. The sidebar cancels only when the dragged item or its target disappears. A pure reorder from another tab is resolved against the new order on drop, through the same reducer checks, so no corruption is possible.
- **An empty-string id cannot be dragged.** Import validation allows an empty id, but the namespaced drag id would be empty after its prefix, so the grip does nothing for that row. The Move menu works for it.
- **`aria-expanded` is stale during a category drag.** While a category is dragged every project list is closed visually and its items unmounted, but the toggles keep their pre-drag `aria-expanded`. The collapse is visual only and lasts for the drag. Focus stays on the grip.
- **Dropping a project on a collapsed category opens it.** This goes beyond the original brief. It matches the Move menu, which already opens the target category. For owner confirmation (ADR 0001).
- **Caret ranges for dev dependencies.** `package.json` uses caret ranges for dev dependencies, with `next`, `react` and `react-dom` pinned. Fine with a lockfile.
- **Cross-tab write shown clamped.** When an older tab writes over-limit data, this tab shows it clamped while storage keeps the original until the next save.
- **Surrogate pair cut.** A name cut at 120 characters can split a surrogate pair. Cosmetic.
- **CI audit gate covers dev dependencies.** It can turn red on a dev-only advisory.
- **Same-version additive fields.** Unknown fields are stripped on load, so newer data with the same `STORAGE_VERSION` would lose fields in an older build. Covered by the README rule to bump `STORAGE_VERSION` on any schema change.
- **Dependabot is off.** The owner switched it off in the repository settings. `.github/dependabot.yml` still exists, with no ignore rules for TypeScript or `@types/node` major versions (PRs #12 and #13 were closed for that reason). Dependency updates are manual until it is switched back on.

## Advisories and unverified areas

- **Safari and Firefox are untested.** This covers the keyboard-versus-mouse focus split after a delete (it relies on keyboard clicks having `detail` 0, and Playwright checks Chromium only), focus after a rename (the focus-restore effect only acts when `activeElement` is `<body>` and is Chromium-tested only), Safari download timing (the object URL is revoked after one second), and the Unicode duplicate check on other platforms.
- **iOS Safari, Android Chrome and VoiceOver are unverified for dragging.** Touch was emulated in Chromium only: a swipe on a project name scrolls an overflowing list without starting a drag, and a touch drag on a grip moves a project. Real devices and a real screen reader need a manual check.
- **React Strict Mode is covered only by a manual dev check.** Playwright runs a production build, where Strict Mode does nothing, and no automated test runs the sidebar drag under it.
- **dnd-kit classic API is frozen upstream.** `@dnd-kit/core` 6.3.1 and `@dnd-kit/sortable` 10.0.0 are pinned. Adding dnd-kit modifiers or upgrading needs a scrolled pointer drag re-tested in a browser, because `pointerDrop()` relies on 6.3.1 internals.
- **The sidebar is very short on a phone.** On a 390x700 viewport the sidebar leaves about 40 px of list height, which makes drags fiddly (auto-scroll starts at once). The Move menu is unaffected. This is a pre-existing layout issue for the design backlog (`ux-ui-designer`).
- **CI has not yet run against the new lockfile.** The dnd-kit packages changed `package-lock.json`, so the Dependency audit job has not seen it. It runs on the pull request.
- **A very fast first arrow key can be ignored.** dnd-kit's keyboard sensor attaches its keydown listener in a `setTimeout` after the pick-up (`@dnd-kit/core` 6.3.1, `core.esm.js` around line 1158), so an arrow pressed in that gap is not seen. When the next position is outside the scroll container, the sensor scrolls first and moves on the following key (around lines 1278 to 1285), so keys pressed back to back can seem to skip a step. Neither comes from the app's state. The dropped move is always the last announced position. The Playwright specs wait for the pick-up to settle and pause between steps; a person pressing keys at normal speed would not notice. Worth a look if users report a missed first key.
- **Deferred minor in the drag code.** `resolveProjectDrop` does not validate that an `hdr` or list category exists; the reducer rejects it, so nothing is corrupted.
- **The Move menu may clip on a phone.** The menu is absolutely positioned inside the scrolling sidebar, so with many categories its lower items may be cut off on a small screen. Not checked. The owner should check it by hand on a phone.
- **The weekly audit can stop silently.** GitHub disables scheduled workflows in a public repository after 60 days without repository activity (recency not re-verified for this review). Someone should watch for the weekly Dependency audit run going missing.
- **Reduced motion during dragging.** Fixed on 2026-10-25: keyboard steps now scroll instantly when `prefers-reduced-motion: reduce` is set (dnd-kit's keyboard sensor defaulted to smooth scrolling). Pointer auto-scroll is dnd-kit's own stepping and was not checked against the setting.
- **Playwright coverage is thin.** There are four smoke checks plus the sidebar drag specs (`e2e/sidebar-drag.spec.ts`), all in Chromium only. They do not cover the banners, hover or focus states, an open dialog beyond the focus trap, or the Count input.
- **The dialog focus test is loose.** It accepts focus landing on `<body>`, so an escape to the body would pass.
- **`app/global-error.tsx` has no automated test.**
- **The split CI workflow has not run on GitHub yet.** That includes the five job names, the Playwright summary step and both `upload-artifact` steps (the report on every run, traces on failure only).
- **Contrast coverage.** jsdom axe disables `color-contrast`. Contrast is covered only by the Playwright axe runs: one main-screen state, and the sidebar with its grips shown and a Move menu open.
- **Real screen readers.** Announcements (live regions, the banners, the alert on a refused rename) were reasoned from the code and checked with axe, not heard in a screen reader.
- **`<dialog>` behaviour in jsdom.** `vitest.setup.ts` uses a `showModal` and `close` stand-in with no top layer or inertness. Real-browser behaviour is checked only by the Playwright focus test.

## What looks solid

- **Validation and import:** `lib/validate.ts` checks types, integer `count` from 1 to 199, name length up to 120, unique ids, no orphans, and guards `__proto__`. Import is size-capped, validated, confirmed through a modal, and refused if a copy of the current data cannot be kept.
- **Load and migrate:** `lib/migrate.ts` lowers over-limit counts and names with a visible notice, keeps a raw copy first, and drops unknown properties.
- **Undo:** `removedBy` with `RESTORE_ITEMS` restores original positions, skips duplicates and orphans, and handles multi-delete in any order.
- **Persistence:** hydration-safe load in an effect, debounced saves flushed on `pagehide`, `visibilitychange` and unmount, an echo guard and a banner for external writes, load-error blocking so the empty state never overwrites data, a save-error banner, a versioned envelope with a legacy path, and `keepBackup` never overwriting an existing copy (shared by the hook, `error.tsx` and import).
- **Accessibility:** native `<dialog>` with `showModal`, labelled, with focus on the safe button and focus return; an always-mounted live region; accessible names on every control; `aria-expanded` and `aria-controls` on the sidebar tree; `aria-current` on the selected category and project; a global `:focus-visible` outline; `prefers-reduced-motion` handling; a sensible heading order; and an axe run with contrast in a real browser.
- **CI:** read-only permissions, SHA-pinned actions and concurrency cancel. Five parallel jobs with their own timeouts: audit (including dev dependencies), lint and types, Vitest, production build and Playwright. The Playwright HTML report uploads on every run and traces on failure.
- **Error boundaries:** `app/error.tsx` and `app/global-error.tsx` use `retry`, correct for this Next.js version. `error.tsx` refuses to reset if it cannot back up first.
