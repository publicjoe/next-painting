## High

### H1. Unreadable-data backup can fail silently, then "Start fresh" destroys the only copy

Status: Fixed in PR #6, change note `docs/changes/2026-10-24-2335-qa-high-fixes.md`.
Resolved as: `keepBackup` in `lib/backup.ts` never overwrites a different backup (`.bak`, `.bak.2` and so on, up to 20), the banner reports a failed backup honestly, and "Start fresh" opens a confirmation. The dialog says whether a copy exists, the backup failed, or storage could not be read at all.

The original finding, as reviewed:

- `hooks/usePaintingLog.ts:48` swallows a failed `localStorage.setItem(BACKUP_KEY, ...)`, but line 51 still tells the user "A raw copy was kept...".
- "Start fresh" (`:133`) then replaces `STORAGE_KEY` with an empty state, with no confirmation.
- The backup is overwritten unconditionally (`:48`), so a second corrupt load clobbers an earlier backup.
- Worst case: a valid envelope with an unknown future `version`, which `lib/migrate.ts:21` rejects as `null`. Data from a newer app version would be wiped.
- Fix:
  - Track whether the backup write succeeded and word the message to match.
  - Confirm "Start fresh" with `ConfirmDialog`, or disable it, when the backup failed.
  - Do not overwrite an existing `.bak` (keep the first, or use a timestamped key).
  - Add a hook test where `setItem` throws for `BACKUP_KEY`.

### H2. Undo toast is hard to reach by keyboard, and focus is lost after a delete

Status: Fixed in PR #6, change note `docs/changes/2026-10-24-2335-qa-high-fixes.md`.

Resolved as: a keyboard-activated delete moves focus to the new toast's Undo button, the toast pauses while hovered or focused (two separate flags), and a Dismiss button was added. Undo, Dismiss and "Start fresh" return focus to the main area. A mouse delete leaves focus alone.

The original finding, as reviewed:

- Deleting a model, project or category removes the focused button, so focus falls to `<body>`.
- `UndoToasts` renders last in the DOM (`components/PaintLogApp.tsx:292`), so Undo is at the end of the tab order, and the toast dismisses after 8 seconds (`components/UndoToasts.tsx:9`).
- Pause on hover and focus only helps once focus is already inside the toast. Relevant criteria: WCAG 2.2.1, 2.4.3, 3.3.4.
- Fix:
  - After a delete, move focus somewhere sensible (the next row, or the toast's Undo button).
  - Or add a keyboard shortcut for Undo, or keep the toast until dismissed when the delete came from the keyboard.
  - Add a dismiss button and consider a longer timeout.
  - Add an interaction test for the focus target after a delete.

### M1. Status cell colours fail non-text contrast, and red against green is weak for colour-blind users

Status: Fixed on branch `qa-medium-fixes` (merged in PR #7), change note `docs/changes/2026-10-25-0030-qa-medium-fixes.md`. Border contrast is hand-computed; the Playwright axe run found no colour-contrast violation on the main screen.

- The ticked or unticked state is also shown by the tick, so this is not a colour-only failure (WCAG 1.4.1).
- Hand-computed ratios over the composited cell backgrounds:

### Medium

#### N1. A test that cannot fail: "stops listening after unmount"

Status: Fixed on branch `qa-followups` (not yet merged), change note `docs/changes/2026-10-25-0845-qa-followups.md`.

- Unmount flushes and clears `pendingRef`, so a later `flush()` returns early and `setItem` is never called. The test passes even if `removeEventListener('visibilitychange')` is deleted.
- Fix: spy on `document.removeEventListener`, or leave an edit pending so a leaked listener would write.

#### N2. The 9999 count cap can make stored or imported data unreadable, with a misleading message

Status: Fixed on branch `qa-followups` (not yet merged), change note `docs/changes/2026-10-25-0845-qa-followups.md`.

- Before the cap, counts had no upper bound. Stored data with a count above 9999 now fails `isAppState`, which shows the generic "saved data could not be read" banner whose only way out is "Start fresh". The raw copy is kept, but recovery means hand-editing JSON.
- A rejected import shows a generic invalid-file error that does not mention counts.
- Fix (suggested): clamp counts to 9999 in `migrate` or on load, or accept any safe integer in `validate.ts` and cap only in the UI.

#### N3. The Count input draft can go stale, and arrow or spinner changes are not saved until blur

Status: Fixed on branch `qa-followups` (not yet merged), change note `docs/changes/2026-10-25-0845-qa-followups.md`.

- If another tab's write or an import changes `model.count` while the field holds a draft, blur commits the stale draft over the newer value. `InlineEditText` resyncs its draft from the prop, and `CountInput` does not.
- Spinner clicks and ArrowUp or ArrowDown change the visible value but save nothing until blur. The row, counter and sidebar stay at the old number, and closing the tab in that window loses the edit. A screen-reader user gets no committed feedback.
- Fix: resync the draft when `model.count` changes, and commit on spinner or arrow input (for example from `onChange` when the event is not a typed edit, or on `onInput` with a short debounce).

#### N4. CI browser step builds twice, and failures cannot be diagnosed

Status: Fixed on branch `qa-followups` (not yet merged), change note `docs/changes/2026-10-25-0845-qa-followups.md`.

- The `webServer` command runs `npm run build && npx next start`, but CI has already built. The second build adds one to two minutes and risks the 180 second webServer timeout on a cold cache.
- `trace: 'retain-on-failure'` is set but no `upload-artifact` step exists, so traces are lost in CI. `retries: 1` can also mask a flaky failure.
- The step has never run on GitHub.
- Fix: use only `next start` when `process.env.CI` is set, upload `test-results/` and `playwright-report/` on failure, and report retries.

## What looks solid

- **Validation and import:** `lib/validate.ts` checks types, integer `count >= 1`, unique ids, no orphans, and guards `__proto__`. Import is size-capped, validated and confirmed through a modal. Grouping uses a `Map`, and there is no HTML injection surface.
- **Undo:** `removedBy` with `RESTORE_ITEMS` restores original positions, skips duplicates and orphans, and handles multi-delete in any order. The reducer tests are thorough.
- **Persistence:** hydration-safe load in an effect, debounced saves flushed on `pagehide` and unmount, an echo guard for external writes, load-error blocking so the empty state never overwrites data, a save-error banner, a versioned envelope with a legacy path, and `error.tsx` writing the backup before removing the key (now via the shared `keepBackup`, and it refuses to reset if the backup fails).
- **Accessibility:** native `<dialog>` with `showModal`, labelled, with focus on the safe button and focus return; an always-mounted live region; accessible names on every control, including the status checkboxes; `aria-expanded` and `aria-controls` on the sidebar tree; `aria-current` on the selected category and project; a global `:focus-visible` outline; and `prefers-reduced-motion` handling.
- **CI:** read-only permissions, SHA-pinned actions, concurrency cancel, a timeout, and the same lint, typegen, `tsc`, test and build gate.
